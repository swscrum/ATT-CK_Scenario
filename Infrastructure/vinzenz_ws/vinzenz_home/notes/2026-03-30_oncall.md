# 2026-03-30 — on-call notes

Trigger: Apache CPU spike at 02:14 UTC — `noise_monitor` (internal
synthetic-monitoring container, 10.10.0.6) was hammering apache with a
600-rps burst for ~4 minutes. Standard incident response runbook ran:

```
ssh apache 'top -bn1 | head -20'
ssh apache 'sudo grep "noise_monitor" /usr/local/apache2/logs/access_log | wc -l'
```

50k+ entries in 4 minutes, all GET / with a `WaystarMonitor` UA. Apache
didn't fall over — kept up.

## Cause

The synthetic monitor's interval got mis-configured during a tabletop
exercise the day before; someone changed `MONITOR_INTERVAL_SECS` from
60 to 0.01 in the env file and didn't revert.

## Resolution

Restarted the noise_monitor container with the correct interval.
Confirmed back to ~1 hit/min baseline.

## Followup

- Monitor container should have its own sanity check that refuses to
  start with `INTERVAL < 10`.
- Apache access log baseline now has a 50k-entry burst in it that the
  SOC training material has to either explain or excise. Talked to
  whoever maintains the SOC docs — they're going to add an annotation.
