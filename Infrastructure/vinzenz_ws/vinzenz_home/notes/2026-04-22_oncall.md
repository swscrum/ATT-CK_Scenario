Trigger: I noticed `lab-fim` events on `/opt/cleanup.sh` on apache
during this morning's sweep. Three MODIFY events overnight, all between
03:00 and 05:00 UTC.

## Investigation

```
ssh apache 'sudo grep "cleanup.sh" /var/log/persist/lab-fim.log | tail'
```

Confirmed three MODIFY events from `cleanup.sh` rewriting itself —
turns out John's "TODO: revert chmod" comment in the file header is
literally getting rewritten by the cleanup script itself every time it
runs. The `find -delete` step at line 38 doesn't touch cleanup.sh, but
the rotation step at line 42 (`mv /var/log/cleanup.log /var/log/cleanup.log.1`)
opens `cleanup.log` for write which triggers an inotify event on a
symlinked path that ALSO covers the script dir on this image.

False positive. lab-fim is doing what we asked. Maybe tighten the
watched-paths regex so we ignore writes that aren't to cleanup.sh
itself? Open ticket.
